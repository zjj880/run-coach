# 交互冗余分析与简化建议

> 基于 v0.4.1 实际界面盘点（代码位置已标注）。目的：减少重复入口、统一动词、让新用户 5 分钟能上手。

---

## 一、现状：入口清单（按页面）

### 今天（7 张卡 + 5 个链接）

| 入口 | 作用 |
|---|---|
| 起床感受（3 个选项） | 一键打卡 |
| 补充晨间打卡 | 完整打卡表单 |
| 和 AI 教练聊聊 / 继续和 AI 教练聊 | 对话 |
| 调整课表 | 打开当日课调整 |
| 日程与训练时间 | 日程编辑 |
| 立即同步佳明 / 连接佳明 | 同步 |
| N 条活动待归类 → 自动归类 / 打开课表 | 归类 |
| 查看依据 | 展开数据来源 |

### 课表（3 个顶部动作 + 每天 6 个链接 + 3 个导航）

| 位置 | 入口 |
|---|---|
| 顶部 | 设置周期、识别导入、立即同步佳明 |
| 每天 | 日程、＋添加训练、调整、标记跳过、自动归类、＋补记活动 |
| 评估列 | 评估训练 / 查看评估 / 查看数据 |

### 记录（2 个顶部按钮 + 每行 2 个链接 + 2 个视图切换）

| 位置 | 入口 |
|---|---|
| 顶部 | 导入记录、训练周期 |
| 视图 | 活动 / 训练笔记 |
| 活动行 | 改归属、查看评估 |

### 我的（6 张卡、8 个动作）

| 卡 | 入口 |
|---|---|
| 佳明中国区 | 管理佳明连接 / 连接佳明、立即同步佳明、**同步历史活动** |

| AI 接口 | 设置 AI 接口 |

| 佳明同步演示 | 同步演示跑步、模拟数据缺失 |

## 二、冗余点（按严重程度）

| # | 问题 | 现状 | 影响 |
|---|---|---|---|
| 1 | **佳明同步入口 3 处** | 今天「立即同步」、课表「立即同步」、我的「立即同步 / 管理 / 同步历史」 | 用户不知道点哪个；状态不一致时容易困惑 |
| 2 | **导入记录 2 处** | 记录页右上「导入记录」+ 我的「导入训练记录」 | 同一功能两个入口，维护和文案都重复 |
| 3 | **两套"周期"概念** | 课表「设置周期」（起始日+周数）与记录「训练周期」（阶段划分） | 名字几乎一样、作用完全不同，新用户必然混淆 |
| 4 | **评估入口 2 处** | 课表第三列 + 记录页「查看评估」 | 记录页其实更适合"看详情"，评估入口放这里多余 |
| 5 | **归类入口 3 处** | 今天待归类卡、课表每天「自动归类」、导入后自动执行 | 自动执行已覆盖 90% 场景，手动入口过密 |
| 6 | **课表每天 6 个链接** | 日程 / ＋添加训练 / 调整 / 标记跳过 / 自动归类 / ＋补记活动 | 单日信息密度过高，手机上尤其挤 |
| 7 | **同一动作多种叫法** | 同步佳明 / 立即同步 / 管理佳明连接；识别导入 / 导入记录 / 导入训练记录；补记活动 / 添加训练 | 用户需要自己"翻译"这些词 |

## 三、建议的目标结构（简化后）

```
底部导航：今天 ｜ 计划 ｜ 记录 ｜ 我的
```

### 今天（3 块，不再 7 张卡）
1. **今日建议**（深色卡，含休息/饮食，可展开"查看依据"）
2. **晨间打卡**（起床感受 + 展开完整表单；晨间数据折叠在其中）
3. **今日待办**（只在有内容时出现：待归类活动 / 未同步提示 / 可训练时段冲突）

### 计划（原"课表"）
- 顶部只留 **两个**：`周切换` + `⋯`（菜单：设置周期、识别导入）
- 同步状态放在周切换行右侧的小 chip（点击即同步，显示"上次同步 12 分钟前"）
- 每天：主操作 **调整**，其余收进行的 `⋯`（添加训练 / 补记活动 / 日程 / 标记跳过 / 归类）
- 评估列保留「评估 / 查看评估」，仅此一处进入评估

### 记录
- 顶部：`导入记录`、`周期与阶段`
- 活动行只保留「改归属」，评估入口移除（去计划页）
- 训练笔记保持现状

### 我的（只放"设置类"）
- 佳明：管理连接 + **同步历史活动**（同步动作只在今天/计划出现）
- AI 接口、环境温湿度开关、演示数据（折叠为"开发与演示"）

## 四、改造清单（建议顺序）

### P0：消除重复入口（改动小、收益大）
1. 删掉「我的 → 导入训练记录」卡（保留记录页入口）
2. 记录页活动行删掉「查看评估」（评估统一在计划页）
3. 今天页删掉「待归类」卡上的「打开课表」，只留「自动归类」
4. 课表的「立即同步佳明」改为状态 chip（点击同步），与今天页保持同一动作

> 涉及文件：`App.tsx`（约 4 处）、`src/RecordsView.tsx`（1 处）

### P1：合并两套"周期"概念
- 把「设置周期（起始日+周数）」并入「周期与阶段」弹窗：一页里上半部分设课表范围，下半部分划分阶段
- 课表顶部「设置周期」按钮改为「周期」，指向同一弹窗

> 涉及文件：`App.tsx`、`src/PeriodEditor.tsx`（新增周数/起始日字段）、`src/training.ts`（保存时同时更新 cycleStart/weeks）

### P2：收敛课表每日操作
- 每天只留主按钮「调整」+ `⋯` 菜单
- 「＋ 添加训练 / ＋ 补记活动 / 日程 / 标记跳过 / 自动归类」进菜单
- 空白天（无计划无活动）直接显示「＋ 添加训练」

> 涉及文件：`App.tsx`（planContent 单日渲染）

### P3：文案与术语统一

| 保留 | 弃用 |
|---|---|
| 同步佳明 | 立即同步、管理佳明连接 |
| 导入记录 | 导入训练记录、识别导入（课表导入单独叫「识别课表」） |
| 补记活动 | 添加训练（当天已有计划时用「调整」） |
| 训练周期（阶段） | 设置周期（周数）→ 改叫「课表范围」 |
| 活动 / 训练笔记 | 训练记录（与"活动"混用） |

### 不建议动的部分（避免过度简化）
- 评估弹窗内部结构（信息密度合理，且是核心价值）
- 导入预览（去重信息必须让用户看到）
- 训练笔记 5 类（力量/跑技/恢复/比赛/学习）——这是差异化功能
- 佳明同步的历史范围同步（独立入口，不与日常同步合并）

## 五、预期收益

- 首页卡片从 7 张 → 3 块，首屏即可看到"今天怎么练"
- 课表单日操作从 6 个链接 → 1 个主操作 + 菜单
- 全应用重复入口从 6 组 → 0 组
- 新用户理解"周期/阶段"的成本显著下降
